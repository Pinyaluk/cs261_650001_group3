# Task53 · Integration Test UI ↔ API (Sprint 2)

สคริปต์ชุดนี้รันเคสทดสอบตามตาราง Test Case ของ Task34 (`unit_test_ui_sprint2`) ซึ่งปรับให้ตรงกับระบบที่ทำจริงแล้ว
ครอบคลุมหน้าของเจ้าหน้าที่ (U4–U6) และหน้าของช่าง (U7–U8) ด้วยเบราว์เซอร์จริง
ตรวจทั้งสิ่งที่ผู้ใช้เห็นบนหน้าจอ และ request/response ที่หน้าเว็บส่งไป backend

- `case-spec.json` คือรายละเอียดของแต่ละเคส ได้แก่ Preconditions, Test Data, ขั้นตอน และ Expected ที่ปรับแล้ว
  - `auto` สคริปต์รันและตัดสินผลเอง (99 เคส)
  - `manual` สคริปต์แคปภาพไว้ให้ คนต้องเปิดดูเทียบกับ Figma เอง (6 เคส)
  - `na` ไม่เกี่ยวข้องกับระบบที่ทำจริง ระบุเหตุผลไว้แล้ว (3 เคส)
- UI-U4-001 ถึง UI-U4-010 พั้นทดสอบเองแล้ว สคริปต์ไม่รันซ้ำ

## สิ่งที่ต้องมี

- Docker Desktop ที่รันได้ (`docker compose up --build` ของโปรเจกต์นี้ใช้งานได้)
- Node.js 18 ขึ้นไป
- Google Chrome หรือ Microsoft Edge ไม่ต้องโหลดเบราว์เซอร์เพิ่ม

## วิธีรัน (Windows PowerShell)

```powershell
cd tests/sprint2-ui-api
npm install
node run-ui-api.mjs --reset
```

`--reset` จะสั่ง `docker compose down -v` แล้ว `docker compose up -d --build` ให้เอง
เพราะเคสต้องเริ่มจากข้อมูลตั้งต้นใน `database/init.sql` จากนั้นรันทุกเคส ใช้เวลาประมาณ 10–15 นาที

ตัวเลือกอื่น

- `node run-ui-api.mjs` รันกับระบบที่เปิดอยู่แล้ว ต้องเพิ่ง `docker compose down -v` และ `up --build` มา ถ้าข้อมูลไม่ใช่ข้อมูลตั้งต้น สคริปต์จะหยุดและบอกให้ reset ก่อน
- `node run-ui-api.mjs --headed` เปิดหน้าต่างเบราว์เซอร์ให้ดูขณะรัน
- `node run-ui-api.mjs --only=UI-U6-014,UI-U6-015 --force` รันเฉพาะบางเคส ใช้ตอนแก้บั๊กแล้วอยากรันซ้ำ

## ลำดับการรัน

ต้องรันตามลำดับนี้ เพราะเคสช่วงหลังเปลี่ยนข้อมูลในฐานข้อมูล

1. **Phase A** ใช้ข้อมูลตั้งต้นอย่างเดียว ไม่มีการเปลี่ยนสถานะคำร้อง
   - ใช้คำร้อง #1024, #1021 (รอรับเรื่อง) / #1019, #1020 (tech03) / #1003, #987 (เสร็จสิ้น)
   - เคสที่จำลองการเชื่อมต่อขาด ใช้วิธีตัด request ในเบราว์เซอร์ ไม่ได้ปิด backend
2. **Phase B** สร้างคำร้องเพิ่ม 5 ใบผ่าน API ของผู้พักอาศัย ถ้าเริ่มจากฐานข้อมูลใหม่จะได้เลข #1025–#1029
   - **#1025** ไฟฟ้า แนบ 2 รูป → มอบหมาย tech01 แบบเร่งด่วน → tech01 ส่งมอบ ใช้กับเคส UI-FIG ทั้งชุด
   - **#1026** ประปา ผู้แจ้งติ๊กเร่งด่วน → กำหนดวันนัดใหม่ + tech04 + ปกติ (UI-U5-008, UI-U6-014, UI-U6-015)
   - **#1027** เปิด 2 หน้าต่างพร้อมกัน (UI-U5-011)
   - **#1028** กดมอบหมายซ้ำ → tech01 กดส่งมอบซ้ำ (UI-U6-016, UI-U8-015)
   - **#1029** ความเร่งด่วนบันทึกพร้อมการมอบหมาย tech02 (UI-U5-007)
   - tech03 ส่งมอบ #1020 (UI-U8-011, UI-U8-012)

## ผลลัพธ์

แต่ละรอบจะเก็บไว้ในโฟลเดอร์แยก `results/<วันที่_เวลา>/` โฟลเดอร์ results ไม่ขึ้น Git ให้แนบรูปหลักฐานในการ์ด Trello แทน

- `ui-api-results.md` สรุปผลรายเคส และรายละเอียดที่ตรวจ
- `ui-api-results.csv` มีคอลัมน์ TC ID / Actual Result / Status / Bug ID / Evidence เรียงตรงกับแถว UI-U4-011 ถึง UI-FIG-U8-08 (แถว 12–119) ก๊อปคอลัมน์ Actual Result / Status / Bug ID ไปวางที่ J12 ได้เลย
- `ui-api-results.json` ผลแบบให้เครื่องอ่าน ส่งไฟล์นี้ให้ Scrum Master กรอกตารางให้
- `<TC ID>.png` รูปหลักฐานรายเคส มีหน้าเว็บ ตาราง request ไป backend และผลการตรวจ
- `<TC ID>_<ชื่อ>.png` ภาพเพิ่มเติมสำหรับเคส manual และ UI-COMMON-001

ความหมายของ Status

- `Pass` / `Fail` สคริปต์ตัดสินเอง
- `Not Run` เคส manual ที่รอคนตรวจจากภาพ
- `N/A` ไม่เกี่ยวข้องกับระบบจริง
- `Blocked` สคริปต์รันเคสนั้นไม่ได้ เช่น ระบบล่มระหว่างรัน
